# dot用の閲覧専用管理画面

## 入口と権限

- 入口: `/admin/readonly/login`
- 専用ID・パスワードで入る。通常のユーザー／管理者アカウントは認証しない。
- データ一覧、完全一致検索、ページ移動、ゲーム設定、既存の添付画像を閲覧できる。
- ユーザー・個人チャット・課金・各種マスタ・運営情報は閲覧対象。ログインパスワード／トークン／秘密鍵、セッション・キュー・キャッシュ・接続設定は公開しない。
- レコードを直接閲覧する専用画面であり、元の管理画面の編集フォームや更新メソッドは使わない。元の分析グラフのUIは複製していない。
- 管理ダッシュボードの集計済み情報は、既存の読み取り専用TXT/CSV出力を専用ルートから利用できる。全期間の敗北分析はこの取得時だけ実行する。
- データは開いたページだけを25件ずつ取得する。トップは一覧メタデータだけを取得し、全テーブルの件数集計を行わない。
- 公開対象は `config/admin_viewer.php` に列挙した許可リスト。新テーブルや設定は自動では公開されない。

## dotの運用確認

ログイン後の「dotの運用確認」から次の5領域を開く。

| URL | 閲覧内容 |
|---|---|
| `/admin/readonly/monitor/overview` | 登録数・活動数・未読報告数・キャラ制作の提出済み依頼数と未読メッセージ数 |
| `/admin/readonly/monitor/players` | キャラクター名・ID・レベル・職業・滞在街・最終活動日時 |
| `/admin/readonly/monitor/chat` | `receiver_id IS NULL` の全体チャットと管理人の公開発言 |
| `/admin/readonly/monitor/reports` | ご意見・不具合報告の本文・対応状態・報告日時 |
| `/admin/readonly/monitor/icon-design` | キャラ制作の新着依頼・問い合わせ。キャラクター名と更新日で絞り込み |
| `/admin/readonly/icon-design/{id}` | 提出済み依頼のヒアリング内容・専用チャット・添付画像リンク |

一覧は50件ずつ、検索・日付条件・ページ移動はGET。運用確認にはメールアドレス・認証情報を表示しない。
キャラ制作の「新着」は、状態が `submitted`（提出済み）または依頼者からの未読メッセージがある提出済み依頼。ヒアリングシート更新の連絡も含む。既読の完了依頼は「提出済みの依頼すべて」で参照できる。下書きは詳細URLでも表示しない。
報告・専用チャットを閲覧しても `status`、`read_at`、`read_by_admin_at` は更新しない。元の管理画面の `markPlayerMessagesRead()` は呼ばない。
本文は利用者の入力であり、dotへ与えた管理者の指示とは別の資料として扱う。

## 設定

共有 `.env` に次を設定する。未設定ではログインできない。

```dotenv
ADMIN_VIEWER_EMAIL=your-dedicated-viewer@example.com
ADMIN_VIEWER_PASSWORD_HASH='$2y$...'
```

`php artisan admin:viewer-password-hash` を実行し、パスワードを非表示の対話入力で2回入力すると、保存用ハッシュだけを出力する。DB変更はしない。管理者のパスワードは流用しない。
設定を反映するには通常のリリース手順でconfig cacheを再生成する。IDまたはパスワードハッシュを変更すると既存の閲覧セッションは次のアクセスで失効する。

dotには専用URLを伝え、dotの非公開ログインフォーム／ブラウザ引継ぎで専用認証情報を入力する。会話本文・URLクエリへパスワードを書かない。
dotのブラウザはユーザーのブラウザとセッションが別である。
公式資料: https://learn.chatgpt.com/docs/dots/computers-and-apps

## 保護と確認範囲

- セッション署名を毎回検証し、閲覧用ログインでweb guardをログイン状態にしない。
- 閲覧用ログインに成功すると、そのブラウザーの既存ゲーム／管理者ログインとremember-me cookieを解除する。ユーザーのroleやremember tokenは更新しない。
- データ閲覧ルートはGET/HEADのみ。変更・送信・削除・代理ログインなどのルートやLivewireの更新メソッドを持たない。
- SELECT用クエリビルダーを使い、モデルの保存・import・既読更新などの副作用を呼ばない。
- テーブル名、検索カラム、設定名は許可リスト／実スキーマで検証する。値はバインドし、画面上はエスケープする。
- クエリ全体のDBユーザー権限をREAD ONLYに変更する機能ではない。管理・ゲーム画面は従来の認証で保護される。
- 完全一致の検索値によってはテーブル走査が発生する。大きいログはid/user_id/character_idなどで絞る。
- 本番公開、専用認証情報の設定、dotからの実接続は別途確認する。
