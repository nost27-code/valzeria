# 通常連続探索・図鑑のまとめ保存と監査整合性

2026-10-08。第1段階 `831d27b9253c61762423dbb77ecda8d1772a0fcb` からのローカル追加実装。読取再利用・図鑑集約とも既定OFF、本番未反映。全状態をメモリで処理する方式や報酬の一括保存は未実装。

## 現在の仕様と今回の実装

50回を50回の逐次判定として維持する。第1段階の条件（読取切替ON、NAM機能ON、通常エリア、複数回、標準runner）に加え、`EXPLORATION_BATCH_DISCOVERIES_ENABLED=true` の場合だけ敵図鑑の保存を敵ごとに集約し、初戦・初勝利の確認を操作内で再利用する。

図鑑の初遭遇時刻・初討伐時刻・最終討伐時刻・討伐回数を保持する。既存の最初の時刻を上書きせず、回数はSQLで原子的に加算する。同じ敵50勝の図鑑書込は150本から3本。敵がE種類なら、通常はINSERT1本＋勝利した敵ごとのUPDATE2本であり、どの探索でも3本になるわけではない。図鑑を操作途中に読む既存の `EnemyBookService` は先にflushして最新記録を返す。

`ExplorationBatchWriteContext` は冒険者行の排他を取得済みのtransaction内だけ有効。正常な途中停止では完了済みの戦闘だけをflushする。例外ではpendingを破棄。savepoint開始時の配列を保持し、内側rollbackでその戦闘の追加分だけを戻す。内側commit後に親のsavepointがrollbackする場合や、途中flushをrollbackする場合も二重計上を防ぐ。別冒険者の記録は旧処理を使う。

初戦・初勝利は既存の一意制約と作成処理を利用し、DBで両記録の存在を確認できた場合だけ確認を再利用する。既存処理がQueryExceptionを捕捉した場合に成功と推測しない。未確認なら次回に再試行し、関連行の変更・rollbackでも無効化する。

性能保存へ方式 `batch_discoveries` を追加し、管理画面で「まとめ読取＋図鑑記録」を分けて比較できる。500でも実行した方式を記録するが、成功した50回としては記録しない。古い記録・再送で方式が不明な場合は未記録のまま。DB構造、migration、seed、マスタID、課金・通貨ルール、プレイヤー画面には変更なし。

## 後回しにしない保存と理由

| 対象 | 今回の扱い | 境界の根拠 |
|---|---|---|
| 戦闘履歴・telemetry | 各戦闘で即時保存 | 作成したBattleLogの実IDを国家貢献・支援完了が同じ戦闘中に参照。初心者ミッション等にも履歴読取がある |
| Gold増減 | 各増減の残高と台帳を逐次保存 | GoldServiceが増減ごとの `amount` と `balance_after` を保存。合計1行への置換は監査粒度を失う |
| EXP・職業成長・能力・HP/SP | 各戦闘で既存処理を実行 | 次戦の能力、HP警告、報酬・成長の閾値に影響する |
| 素材・装備・印・卵・探索進行 | 既存の保存・hookを維持 | 装備取得には図鑑hook、ドロップには実ID、印には能力閾値、探索には深度/停止判定がある |
| 国家貢献・支援・公開ログ・計測 | 既存の呼出順を維持 | BattleLogに結びつく記録や補助効果消費を集約しない |
| 操作UUID・暗号化結果 | 最後に既存middlewareで保存 | 図鑑flushを含む全処理を同じ外側transaction内で確定。再送は保存先へ戻り再実行しない |

既存の輝石処理と戦闘ログの結び付けには変更しない。BattleLogの仮IDや代替UUID、途中commit、自動再実行は導入しない。

新経路の失敗時の違い：旧図鑑記録は戦闘中の例外を報告して継続する補助処理だった。新しいまとめ保存のflushが失敗した場合は成功扱いせず、操作全体をrollbackする。取得済み報酬が本番で消える変更ではなく、この未確定操作を一切確定しない。別の切替を既定OFFとし、この可用性と整合性の違いをstagingでも確認してから有効化する。

図鑑の既存行IDは維持する。新規行の自動採番はINSERT集約によって旧処理と異なる可能性がある。図鑑の論理キーは冒険者×敵であり、現行コード・migrationには図鑑行IDを参照する資産/台帳のFKはない。複数敵の比較は初遭遇/討伐日時・回数等の全業務列と既存IDを照合し、新規採番の一致を要求しない。

## 整合性確認

- 確認済み：実際の連続探索ループ、LevelService、GoldService、BattleLogService、図鑑、初戦/初勝利を使い、旧保存と新保存を比較。戦闘結果と探索力は試験用の固定結果に置換する。50回完了、HP不足、探索力枯渇、敗北、時間切れ、特殊イベント、開始前の探索力不足/HP不足の8条件で、結果・成長・職業・Gold・全台帳残高・戦闘履歴・図鑑・初戦/初勝利が一致。
- 確認済み：既存討伐回数・最初の時刻を保持し、敗北→初勝利、複数敵、別冒険者、nested commit/rollback、途中flush後rollbackを照合。
- 確認済み：隔離SQLiteの試験用triggerで、Gold残高変更後の台帳INSERT、図鑑flush、図鑑保存後の操作結果INSERTを意図的に失敗させた。前の戦闘も含めGold・履歴・図鑑・初戦/初勝利・操作記録をrollback。結果保存の失敗ではsessionも復元し、同じtokenで再試行可能。
- 確認済み：同一UUID再送では再付与/再記録なし、要求内容を変えた再送は409。暗号化した停止結果を復元し、完了数/停止理由を照合。初勝利記録の失敗は次回に再試行し、保存が確認できた後だけ重複確認を省く。
- 確認済み：追加・関連テスト37件／433assertions。既存の回帰116件／1,077assertionsを両切替ONで実施。探索・補助・timeout・護符・NAM戦闘/構造・図鑑・運営の初回操作集計・設定snapshot・探索state・印を対象にした。2つの実行はそれぞれの対象・設定とともに記録する。
