# 名もなき鍛冶屋のOFF配備

2026-10-06の本番配備基準はbd909cf66d9fc25c474c0ade73f141cc60cd1199。本版の共通倉庫・武具獲得率は後続の機能OFF配備対象。実際の最新SHAと成功はrelease-sha/Actionsと読戻しで確認する。コード・画像をstaging→productionへ同一SHA・migration_mode=noneで配備済み。機能OFF、対象5本の本番migration未適用、工房街0件を読取確認した。今夜の準備/有効化手順の正本は `NAMELESS_RELIC_ACTIVATION.md`。

## 現行の停止・有効化条件

`NamelessWorkshopService::enabled()`は全環境で正式設定 `NAMELESS_RELICS_ENABLED` を参照し、既定OFF。`ready()`は設定ONと `NamelessSchemaService` による対象5本の移行記録・全必要列/型/制約の完了を要求する。production/stagingでも、この条件を満たせば有効化できる。旧ローカルキーだけでは本番を開かない。

OFFでは工房・遺跡・MAP入口・追加装備表示・新しい能力加算/特殊効果を停止する。登録済み街も非公開。該当schemaが存在する場合、既存装着資産の売却/消費/所有者変更の保護、進化先への継承、敗北喪失時の取り外しはOFFでも維持する。正式レイドの受付済み出撃は保存済み承認契約で精算する。

## 配備範囲

- 名もなき武器9種・防具6種・装飾品5種、収集・命名・保護・+99育成・吸収・付け替え。
- 遺物87種×I〜IX、通常SSS2枠/EPIC3枠、名もなき武具3枠。I〜VIは本体込み3個、VII〜VIIIは5個で次ランクへ。途中進捗・確認・UUID再送対策。
- 6遺跡、深度別ボス、ボス挑戦ボタン、入手できる遺物のアコーディオン。関連武具・遺物・敵・街画像。

2026-10-06の追加裁定では固定60個/300個を廃止し、武具は装備倉庫・遺物は素材倉庫の共通容量を使用する。装着/保護/育成中も1個体1枠で、OFFでも所有分を数える。共通倉庫化は機能OFFの配備対象。武具本体の獲得率も追加裁定により深度1の0.1%から深度100の1%へ直線補間し、0.01%単位に丸める。深度50は0.55%。遺物ランク抽選は維持し、武具は各勝利につき独立1回・最大1個・天井なし。この変更も機能OFFの配備対象で、正式ONは未実施。

## DB準備と正式公開

`nameless:prepare --json` は状態確認のみ。OFFのまま `nameless:prepare --apply --register-town --json` で対象5本だけの移行と街登録を準備できる。既存資産のバックアップと事前/事後照合を行い、部分DDL失敗は診断して停止する。無関係なmigrationの一括適用や全体seedは行わない。

準備完了はenabled=false、pending_migrations=[]、schema_ready=true、schema_problems=[]、town_count=1とコマンド終了0をセットで確認する。現時点では本番でこの準備を実行していない。倉庫・武具獲得率の追加裁定を反映し、隔離ONの最終確認と本番OFFの回帰確認を済ませてから、別のON指示で有効化する。

## 検証と復旧

隔離MariaDBの移行/既存資産保持/街登録の同時操作、SQLiteの機能テスト、mysql/mariadbドライバの直列CIを実施済み。最新コードのCI、公開SHA、6,734ファイル、健康状態、認証境界、OFFの画面描画、設定/DB台帳/承認契約の保持、配備後ログと戻し先を確認した。本番ON実操作と実機スマホは未確認。

正式ONの操作はNAMELESS_RELICS_ENABLED=trueと設定cache再生成。常駐workerがあれば新設定を反映し、公開後の最終操作/ログを確認する。問題時は現行コードを維持してOFFとcache更新へ戻し、所有資産・DBは保持する。資産を消すmigration downや、保護/継承を欠く旧版へのコード巻戻しは通常復旧に使わない。

## 旧版との違い

2026-10-05の旧OFF版d87204daはlocal/testing限定の環境ゲートを使っていた。後続修正で正式設定を全環境へ統一し、OFF時の資産保護・継承を追加した。旧版の停止条件や「flagだけでは本番を開けない」を現行の有効化手順に流用しない。設定ONだけでDB不足や街未登録を解消できるという意味でもない。
